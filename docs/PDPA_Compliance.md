## 1. Introduction

This document outlines the ZynxAGI Platform's compliance with Thailand's Personal Data Protection Act (PDPA) B.E. 2562 and establishes data protection principles for the ethical handling of personal information.

### 1.1 Scope
This policy applies to all:
- ZynxAGI platform users and interactions
- Deeja (น้องดีจ้า) agent communications
- Data processing within the Zynx ecosystem
- Third-party integrations and services

---

## 2. Legal Framework Compliance

### 2.1 PDPA B.E. 2562 Adherence
The ZynxAGI platform operates in full compliance with:
- **Section 19**: Lawful basis for personal data processing
- **Section 24**: Data subject consent requirements  
- **Section 30**: Data subject rights and access
- **Section 35**: Cross-border data transfer restrictions
- **Section 41**: Data retention and deletion obligations

### 2.2 Data Controller Responsibilities
**Chanont Wankaew / Zynx Thailand** serves as the Data Controller with responsibilities for:
- Determining purposes and means of processing
- Ensuring lawful basis for all data collection
- Maintaining data processing records
- Implementing appropriate security measures

---

## 3. Data Collection and Processing

### 3.1 Types of Data Collected
**Personal Data Categories:**
- User interaction logs (chat messages, preferences)
- Cultural context information (language, region)
- Technical metadata (timestamps, session data)
- Emotional response patterns (for Deeja's empathy calibration)

**Special Categories (requiring enhanced protection):**
- Cultural and religious preferences
- Emotional state indicators
- Sensitive personal opinions or beliefs

### 3.2 Lawful Basis for Processing
- **Consent**: Explicit user consent for cultural personalization
- **Legitimate Interest**: Service improvement and Thai cultural AI development
- **Legal Obligation**: Compliance with Thai data protection laws

### 3.3 Purpose Limitation
Data is processed exclusively for:
- Providing culturally intelligent AI responses
- Improving Deeja's empathetic capabilities
- Maintaining system security and integrity
- Research and development (anonymized data only)

## 4. Consent Management

### 4.1 Consent Requirements
- **Clear and Specific**: Users understand what data is collected
- **Freely Given**: No coercion or bundled consent
- **Informed**: Comprehensive information about processing
- **Withdrawable**: Easy mechanism to withdraw consent

### 4.2 Consent Mechanisms
```
[✓] I consent to ZynxAGI processing my interaction data to provide 
    culturally intelligent responses through Deeja (น้องดีจ้า)
    
[✓] I consent to anonymous usage analytics for improving Thai 
    cultural AI capabilities
    
[ ] I consent to data processing for research purposes (optional)
```

### 4.3 Consent Withdrawal
Users can withdraw consent at any time through:
- Platform settings interface
- Email request to: zynx.ai.thai@gmail.com
- Automated consent management system

---

## 5. Data Subject Rights

### 5.1 Right of Access (Section 30)
Users may request:
- Confirmation of data processing
- Access to personal data held
- Information about processing purposes
- Details of data recipients

### 5.2 Right to Rectification
Users can request correction of:
- Inaccurate personal data
- Incomplete information
- Cultural preference updates

### 5.3 Right to Erasure ("Right to be Forgotten")
Applicable when:
- Data no longer necessary for original purpose
- Consent is withdrawn
- Data processed unlawfully
- Required by legal obligation

### 5.4 Right to Data Portability
Users can obtain their data in:
- Machine-readable format (JSON)
- Structured, commonly used format
- Transferable to another service

---

## 6. Data Security Measures

### 6.1 Technical Safeguards
- **Encryption**: AES-256 encryption for data at rest
- **Hashing**: SHA-256 for data integrity verification
- **Access Controls**: Role-based access limitations
- **WORM Storage**: Immutable storage for audit trails

### 6.2 Organizational Measures
- **Staff Training**: PDPA compliance education
- **Access Monitoring**: Audit logs for all data access
- **Incident Response**: Data breach notification procedures
- **Regular Audits**: Compliance assessment and improvement

### 6.3 Data Breach Response
**Within 72 hours of discovery:**
1. Assess breach severity and scope
2. Notify relevant authorities if required
3. Inform affected data subjects if high risk
4. Document incident and remedial actions

---

## 7. Cross-Border Data Transfer

### 7.1 Transfer Restrictions (Section 35)
- Personal data remains within Thailand unless:
  - Adequate protection level in destination country
  - Appropriate safeguards implemented
  - Explicit user consent obtained

### 7.2 International Collaboration
For global AI research collaboration:
- Data anonymization before transfer
- Aggregated insights sharing only
- No personal identifiers in shared data

---

## 8. Data Retention and Deletion

### 8.1 Retention Periods
- **Interaction Logs**: 12 months (unless consent withdrawn)
- **User Preferences**: Until account deletion
- **Anonymized Analytics**: 7 years for research
- **Audit Logs**: 7 years for compliance

### 8.2 Automated Deletion
System automatically deletes:
- Expired temporary data
- Data of withdrawn consent
- Inactive user accounts (after 2 years notice)
